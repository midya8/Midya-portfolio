# ProvLab

Compare provenance on one supplied database, set containment over all databases and containment under supplied full rules and keys. The current suite has 44 Python and 11 Node/actual-Chrome tests; earlier counts below describe their release stages.

## ProvLab: one fact is not two chances

[Live workbench](https://midya8.github.io/provlab/) | [Source](https://github.com/midya8/provlab) | [Method and sources](https://github.com/midya8/provlab/blob/main/METHOD.md)

A self-join can use one fact twice without giving it two independent chances to exist. Shared query variables enforce joins; projection and union-all collect derivations into natural-coefficient polynomials. The default `p² + pq` has bag multiplicity `10` and exact answer-presence probability `1/2`. Substituting probabilities into the ordinary polynomial gives `3/8`, an intentionally invalid contrast. Reusing a token is one event, not a fresh draw.

Inspect fourteen original controls, partial join bindings, every derivation, witness sets, minimal Boolean witnesses and every possible-world mass. A native checker enumerates active-domain valuations and re-queries possible databases rather than calling the join generator. Actual SQLite token-carrying joins feed a separate SymPy polynomial check. The original browser workflow checks every output and world at 1280/390/320 pixels and completes fourteen downloads replayed natively. Fresh installed checks replay all fourteen controls through both CLI entry points outside the checkout, check five import origins and reject twenty forged reports.

The core uses exact rational arithmetic and has no runtime dependencies. It implements classical provenance semirings and tuple-independent base-event semantics, not new theory, arbitrary SQL, scalable database inference, calibrated probabilities, causal effects or a guarantee about an AI agent. Established theory and inspected sources are credited in the method.

## ProvLab 0.2: same answers on every database

[Containment lab](https://midya8.github.io/provlab/containment.html) | [Source](https://github.com/midya8/provlab) | [Exact contract and sources](https://github.com/midya8/provlab/blob/main/CONTAINMENT.md)

A rewrite can agree on one database and fail on another. This mode compares safe positive conjunctive queries over every finite database under set semantics. A head-preserving reverse homomorphism proves containment; a failed direction produces a frozen canonical database and a missing output tuple. Inspect every variable-map candidate, atom image, ordered head constraint, canonical evaluation and safe atom-subset minimum. Constants stay fixed, Boolean heads and ternary relations are explicit, and repeated atom occurrences remain visible.

Set-equivalent is not bag-equivalent. The repeated-fact control preserves the answer set but changes a multiplicity-two probe from `4` to `2` and natural provenance from `f0²` to `f0`. A separate native generator and active-domain replay checker handle this mode. The historical v0.2 suite had 32 Python tests, including 235 single-field corruption rejections and 80 direct finite-instance checks. All remain in the current suite. The 112 complete cross-language comparisons cover 17,403 candidate maps and 1,662 subset rows. Actual SQLite DISTINCT/ALL/token joins run 1,344 queries; SymPy checks 362 polynomials built from those token rows.

Fresh installed checks replay twelve containment controls through both entry points, check five import origins and reject twenty forgeries. Actual Chrome checks 36 reports, 72 directions, 1,260 candidate selections, 240 subset selections and twelve completed downloads replayed natively. These are bounded fixture checks, not a scalability benchmark or proof of the classical theorem.

The method credits Chandra-Merlin query-containment/core theory. This is bounded single-CQ syntax, not a bag-equivalence decision procedure, arbitrary SQL optimization, new theory, a language model or a verified-agent guarantee. The original provenance mode remains separate.

## ProvLab 0.3: containment under supplied constraints

[Chase workbench](https://midya8.github.io/provlab/chase.html) | [Source](https://github.com/midya8/provlab) | [Exact contract and sources](https://github.com/midya8/provlab/blob/main/CHASE.md)

A rewrite that fails in general can hold under a supplied key and rule. Full rules add facts; keys merge query symbols in both the database and ordered output tuple. Inspect both containment directions, every chase step, terminal dependency check, source derivation and legal saturated counterexample. A clash between distinct literals is labeled target-query unsatisfiability and vacuous containment, not a successful nonempty rewrite.

Every dependency subset is tested. The default needs a key plus a diagonal rule; neither alone suffices, and a symmetry rule is irrelevant. Another control separates a one-rule minimum support from a two-rule inclusion-minimal support. The current suite passes 44 Python and 11 Node/actual-Chrome tests, retaining the provenance and unconstrained-containment workflows. Checks include 114 complete native/JavaScript reports, an independent ground replay and rejection of 344 changed primitive evidence fields. Actual SQLite checks 7,618 queries and 5,858 sound containment implications across those 114 reports.

Fresh installed checks replay fourteen chase controls through both entry points, check five import origins and reject twenty forged CLI reports. Actual Chrome checks fourteen controls at 1280/390/320 pixels: 42 reports, 84 directions, 171 trace states, 141 subset selections and fourteen trusted downloads replayed by Python. Coverage counts describe the committed fixtures, not a general proof.

This is bounded classical database theory with full single-head rules and relational keys. It does not implement existential chasing, arbitrary EGDs, SQL NULL, bag-preserving optimization or global constrained query minimization. A valid rewrite under supplied constraints is not evidence that those constraints hold in a real database. The original provenance and unconstrained-containment modes remain available.
